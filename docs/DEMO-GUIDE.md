# AffinityQA — reviewer walkthrough

This guide describes the restricted interactive demo of a verified recorded capture. It executes the routing, diagnosis and supported repair workflow using recorded model decisions. It makes no new model or Qloo calls. A recording of this walkthrough is optional and cannot substitute for the functional application.

## Choose the right installation

The hosted reviewer demo is the intended primary entry point. Its public address is pending approval and external verification. For a private rehearsal, use the restricted surface prepared in [the deployment guide](PUBLIC-DEMO-DEPLOYMENT.md). A verified matching evidence package must be separately authorized and supplied.

The source-only package contains code and synthetic engineering tests. Without that evidence it shows UNAVAILABLE, rather than inventing a demonstration. The local judge archive is a different package: it contains compiled interface assets and private recorded evidence and starts the complete local studio. The local studio retains historical studies; it must not be exposed through a public tunnel.

| 1:25–1:45 | Choose **Verify** and inspect all six checks. | Recovery requires a supported diagnosis, an applied repair, restored profile integrity, a dispatched decision, a healthy match and legitimate cache reuse. | 1:45–2:00 | Open **Protocol & provenance** and show the retained historical quality results. | The original capture used 234 real local model executions and 24 total Qloo requests, with 54 observed recoveries over three repeats per case. The fault is deliberately injected in a controlled adapter. Describe it as an integration incident; do not claim discovery of an undisclosed production incident or a general-purpose code repair.

## Additional checks a reviewer can run

| Incident | Expected diagnosis | Supported repair | Recorded decision dispatches |
| --- | --- | --- | --- |
| Profile missing from cache key | CACHE_OMITS_PROFILE | set-profile-cache | 3 |
| Stale profile passed to agent | STALE_PROFILE | restore-request-profile | 4 |
| Qloo context bound to wrong profile | WRONG_TOOL_PROFILE | bind-request-tool | 4 |

Choose any of the six artist pairs and repeats 1, 2 or 3. Repeats 1 and 3 request the second artist after the first; repeat 2 requests the first artist after the second. Changing the selection clears the previous result. The interface requires the returned selection to match the request.

The 18-case denominator is six pairs multiplied by three incident types. Each case has three recorded repeats, giving 54 repeat-level recoveries in the source capture. Replaying one selection does not add to that validation denominator or create another independent trial.

## Reading the gates

**Causal integrity PASS** means the specified controlled integration checks passed. **Cultural quality NOT_VALIDATED** means the observed recovery does not establish an individual's movie preferences. **Tested agent release BLOCKED** retains the separate recommender quality approval; it does not turn a verified recorded replay into a failed execution. The earlier development result 13/14 and separate quality trial 4/6 remain rejected under their original gates.

The original capture made real Qloo requests and obtained fresh local-model decisions before and after repair. This reviewer replay re-executes the causal workflow against those captured decisions. The separate verifier checks recorded evidence and source bindings; it is not an external service attestation or a human preference study.

## Unavailable and busy states

An absent, altered or mismatched capture must not produce a verified result. A source preview showing UNAVAILABLE needs the separately authorized evidence; the message is not a substitute for a working submission. The operator must verify the actual public address before presenting it to the judges.

Only one replay can run at a time in the restricted server. If another request is already running, the interface reports that the demo is busy. Wait for the active request to finish, then retry the selected incident. A previous selection's result must not appear as the result of the new request.

## Submission operator checks

Before the separately approved publication and submission, bind the materials to the actual public application URL and repository revision. Test the external address, six pairs, three incident types, all repeats, named provenance, keyboard, narrow-screen layout and error handling. Check that raw local run exports and live model jobs remain inaccessible from the restricted application. Confirm the applicable Qloo display permission and continued free judge access through the judging period. [Official rules](https://qloo.devpost.com/rules)
